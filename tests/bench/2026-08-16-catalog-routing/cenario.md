# Catalog routing and boundary review

## Objective

Clarify canonical ownership and `Use when`/`Avoid when` boundaries without reducing discoverability or breaking repository validation.

## Baseline

- Repository validation: 39 catalogs and references pass.
- Worktree: clean and synchronized with `origin/main`.
- Existing routing covers probability/statistics and urban/territorial planning.

## Acceptance criteria

- Decision uncertainty routes to `08`; statistical/probabilistic inference routes to `37`.
- Canonical owners and secondary specializations are explicit for representative cross-domain families.
- Every method card retains a usable trigger and a concrete misuse boundary.
- Crisis/continuity capabilities remain distinguishable by output and authority.
- Validation, local-link checks, and diff checks pass.

## Adversarial checks

- A prompt containing only “uncertainty” must not be forced into one catalog without identifying the required output.
- A domain specialization must not be treated as a second generic method.
- `Avoid when` must not become a generic disadvantage list or a universal prohibition.
